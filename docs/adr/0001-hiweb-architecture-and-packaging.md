# ADR-0001：HiWeb 效率库的架构分层与打包分发策略

- 状态：已采纳（2026-11-19）

## 背景

在多套 React / Next.js Web 应用与管理后台并发演进过程中，AES-256-GCM 会话密封、结构化脱敏日志、安全 URL 校验、部署环境防串连、统一请求包络解包、SSE 鉴权处理、OpenAPI-Zod 契约核对以及 Base UI + Tailwind CSS 4 基础组件在多个仓库中出现了大量重复复制，并已产生细节分叉与安全漂移。

同时，前端生态在包体积敏感性、Tree-shaking、SSR 并发请求隔离、`server-only` 与 `"use client"` 边界以及单仓 Docker 离线构建方面，与移动端效率库存在显著差异。

## 决策

1. **只聚焦 React / Next.js + 纯 TS 同构底座**：非 UI 基础设施层（`base` / `core` / `net` / `store`）保持纯粹框架无关，UI 层（`suite`）绑定 React 19 + Tailwind CSS 4 + `@base-ui/react`，服务端框架胶水收敛在独立薄包（`next`）。
2. **8 子包单向无环拓扑，不设全量聚合总包**：消费方按运行时需要显式引入独立子包，避免浏览器包误拉入服务端模块或 Node 工具链。
3. **禁止模块级可变全局单例**：全部日志、埋点、错误上报、存储、HTTP 客户端通过工厂函数按实例或请求作用域创建，杜绝 SSR 请求间信息串扰。
4. **面向 npm Registry 与 MIT 协议设计，未发布期采用 40 位 SHA 版本锁 + `.tgz` 本地同步**：在保证每个子包完全达到 npm 公开发布质量的同时，支持消费仓库通过确定性 `.tgz` 离线完成 `npm ci` 与 `Dockerfile` 单仓镜像构建；未来正式发版 npm 后消费侧仅替换依赖声明，业务代码零改动。

## 后果

- 新增或调整跨项目共性能力需严格审查通用性，绝不允许具体业务语义污染 HiWeb；
- `HiWeb` 每次修改需先完成自身 `pnpm run check` 与推送，再同步更新消费项目版本锁。
